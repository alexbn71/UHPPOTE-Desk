À propos de ce manuel

Les captures d'écran proviennent d'une installation de démonstration avec un contrôleur simulé à 4 portes et des personnes fictives : vos noms, numéros et dates seront différents. L'installation (Docker, réseau, variables d'environnement) est décrite dans un guide séparé, docs/DOCKER.md dans le dépôt du projet.

Remerciements

UHPPOTE Desk s'appuie sur la connaissance du protocole publiée par le projet open source uhppoted (codeberg.org/uhppoted). UHPPOTE Desk est un projet indépendant, sans lien avec uhppoted ni avec le fabricant des contrôleurs.

Partie 1

Comprendre UHPPOTE Desk

Ce que fait l'application, comment elle dialogue avec les contrôleurs d'accès et les quelques notions à connaître avant de l'utiliser.

1 · Qu'est-ce que UHPPOTE Desk

UHPPOTE Desk est une application web pour gérer les contrôleurs d'accès UHPPOTE UT0311-L0x (1, 2 ou 4 portes ; ce manuel utilise le modèle 4 portes UT0311-L04). Elle remplace le programme Windows fourni avec les contrôleurs ("Access Control", N3000) par une application moderne qui :

  • tourne sur un serveur ou un NAS (normalement en conteneur Docker) et s'utilise depuis n'importe quel navigateur — PC, tablette ou téléphone — sans rien installer ;
  • est utilisée par plusieurs opérateurs en même temps, chacun avec un rôle (administrateur, opérateur, lecture seule) et, si besoin, limité à certaines zones du bâtiment ;
  • conserve personnes, badges et autorisations dans sa propre base de données et envoie automatiquement chaque modification aux contrôleurs ;
  • reçoit les passages et les alarmes en temps réel, garde l'historique complet des événements et calcule les présences (heures travaillées, retards, absences) ;
  • est disponible en anglais, italien, espagnol, français et allemand ; chaque utilisateur choisit sa langue.

2 · Fonctionnement du système

Une installation de contrôle d'accès comporte trois éléments : les contrôleurs installés près des portes, le serveur où tourne UHPPOTE Desk et les navigateurs des opérateurs.

  • Les contrôleurs décident. Quand un badge est présenté, c'est le contrôleur lui-même qui vérifie si ce badge peut ouvrir cette porte à ce moment, et qui ouvre la serrure. Il ne demande rien au serveur : les portes fonctionnent même si le serveur ou le réseau sont arrêtés.
  • Le serveur est la référence. Personnes, badges, autorisations, plages horaires et réglages sont dans la base de données de UHPPOTE Desk. Chaque modification faite dans l'application est envoyée immédiatement aux contrôleurs joignables. Un contrôleur qui était hors ligne est remis à jour par la Synchronisation.
  • Les événements remontent. Chaque passage, ouverture ou alarme est enregistré dans la mémoire du contrôleur et envoyé au serveur, qui le stocke dans l'historique et l'affiche en direct. Si le réseau était coupé, les événements manquants sont téléchargés dès que le contrôleur redevient joignable : aucun n'est perdu.
Pourquoi c'est important

Ne modifiez pas les contrôleurs avec d'autres programmes (le logiciel Windows d'origine ou la page web du contrôleur) tant que UHPPOTE Desk les gère : à la synchronisation suivante, l'application annulerait ces modifications, car sa base de données est la référence.

3 · Notions de base

Contrôleur

La carte électronique qui gère 1, 2 ou 4 portes. Il est identifié par son numéro de série (9 chiffres sur l'étiquette S/N) et joint sur le réseau par son adresse IP. Il stocke des dizaines de milliers de badges et d'événements.

Porte

Chaque sortie du contrôleur : un lecteur de badges, une serrure électrique (relais), éventuellement un capteur de porte (ouverte/fermée) et un bouton de sortie. Dans l'application, une porte a un nom, un mode de fonctionnement et un temps d'ouverture.

Personne

Quelqu'un qui passe les portes : matricule, nom, service, période de validité, code PIN facultatif pour le clavier, photo et horaire pour les présences.

Badge

Une carte de proximité ou un porte-clés. Son numéro a 8 chiffres au format Wiegand-26 : code site × 100000 + code badge, par exemple 10058400 = site 100, code 58400. Un badge peut être attribué à une personne ou enregistré comme libre.

Autorisation

Le droit d'une personne d'ouvrir une porte : toujours, ou seulement dans une plage horaire. Les autorisations appartiennent à la personne et valent pour tous ses badges.

Plage horaire

Une fenêtre de temps (jours de la semaine, jusqu'à 3 intervalles horaires, dates de validité) numérotée de 2 à 254. Elle peut être liée à une autre plage pour l'étendre, par exemple jours ouvrés + samedi matin.

Événement

Tout ce que le contrôleur enregistre : passages de badge (autorisés ou refusés, avec le motif), porte ouverte/fermée, bouton de sortie, alarmes, mise sous tension, ouverture à distance.

Synchronisation

L'alignement d'un contrôleur sur la base de données. Elle a lieu automatiquement à chaque modification ; la page Synchronisation vérifie et corrige les différences (par exemple après une longue période hors ligne).

Zone et service

Les zones regroupent les contrôleurs (bâtiments, étages) et peuvent limiter ce qu'un opérateur peut commander. Les services organisent les personnes et filtrent les rapports de présence.

Présences

Les passages sur les lecteurs marqués pour les présences deviennent des pointages d'entrée/sortie. Avec les horaires, jours fériés et absences, l'application calcule heures travaillées, heures supplémentaires et retards.

Comment un accès est décidé

Quand un badge est présenté sur une porte, le contrôleur n'accorde l'accès que si toutes ces conditions sont réunies ; sinon il le refuse et enregistre le motif (voir Motifs des événements) :

  1. le badge est enregistré dans le contrôleur (les badges d'une personne inactive, perdus ou désactivés sont retirés des contrôleurs) ;
  2. aujourd'hui est dans la période de validité du titulaire ;
  3. la personne a une autorisation sur cette porte — toujours, ou avec une plage horaire qui inclut le jour et l'heure actuels ;
  4. les règles de la porte le permettent : mode de la porte, interverrouillage, anti-passback, premier badge, et le PIN quand le lecteur a un clavier.

4 · Opérateurs et rôles

Chaque utilisateur de l'application se connecte avec son propre compte d'opérateur. Chaque opérateur a l'un de trois rôles. Les administrateurs peuvent aussi limiter un opérateur à certaines zones : l'ouverture à distance et la synchronisation ne sont alors permises que sur les contrôleurs de ces zones.

6 · Premiers pas

Connexion

Ouvrez l'adresse du serveur dans le navigateur (par exemple http://192.168.1.10:8080) et connectez-vous. Le premier administrateur est admin :

  • si le serveur a été installé avec la variable ADMIN_PASSWORD, utilisez ce mot de passe. Il ne peut être changé qu'en modifiant la variable et en redémarrant le serveur ;
  • sinon, un mot de passe temporaire a été généré au premier démarrage et écrit dans le journal du serveur. Il vous est demandé immédiatement d'en choisir un nouveau.

Après plusieurs mots de passe erronés, le compte est bloqué quelques minutes. Les sessions expirent après quelques heures d'utilisation (12 par défaut).

Première configuration — étapes

  1. Contrôleurs → Rechercher sur le réseau : trouvez les contrôleurs, ajoutez-les et nommez-les (chapitre 17). Si un contrôleur a une adresse IP d'usine hors de votre réseau, changez-la depuis sa page.
  2. Portes : donnez à chaque porte un nom parlant, vérifiez mode et temps d'ouverture et indiquez les lecteurs à utiliser pour les présences (chapitre 18).
  3. Plages horaires : créez les fenêtres horaires nécessaires, par exemple "Heures de bureau" (chapitre 19). Les autorisations valables "toujours" n'en ont pas besoin.
  4. Services et zones : créez l'organisation de l'entreprise et, si vous le souhaitez, les zones du bâtiment (chapitre 15).
  5. Personnes : créez-les une par une ou importez un fichier CSV ; attribuez badges et autorisations (chapitre 12). On lit le numéro d'un nouveau badge simplement en le présentant à un lecteur quelconque.
  6. Opérateurs : créez un compte pour chaque utilisateur de l'application avec le bon rôle (chapitre 22).
  7. Vérifiez dans le Moniteur que les passages apparaissent en temps réel. Sinon, voir Dépannage.
Astuce

Avant l'arrivée du matériel, vous pouvez tout essayer avec le simulateur de contrôleur inclus dans l'image Docker (voir docs/DOCKER.md, "Trying the app without a controller").

Partie 2

Exploitation

La surveillance quotidienne : état des contrôleurs, passages en direct, historique des événements, présences et plaques.

Exploitation

7 · Tableau de bord

La première page après la connexion. Pour chaque contrôleur, elle affiche un panneau avec :

  • le nom, l'état En ligne/Hors ligne, le numéro de série et l'adresse IP, et l'heure du dernier contact. Si l'horloge du contrôleur se trompe de plus de quelques secondes, l'écart est affiché (l'heure est corrigée automatiquement) ;
  • une tuile pour chaque porte active avec son mode (Contrôlée, Normalement ouverte, Normalement fermée), l'état du capteur de porte (Ouverte/Fermée) et l'icône de la serrure, orange quand le relais est actif (serrure libérée) ;
  • le bouton pour ouvrir la porte à distance (opérateurs et administrateurs) : après confirmation, la serrure est libérée pendant le temps d'ouverture de la porte et un événement "Ouverture à distance" est enregistré ;
  • des indicateurs rouges pour Alarme incendie ou Verrouillage forcé quand ces entrées du contrôleur sont actives, et les sorties allumées de la carte d'extension.

En dessous, Derniers événements liste les événements les plus récents de tous les contrôleurs ; les accès refusés sont surlignés en rouge. Ouvrir le moniteur mène au moniteur en direct.

Le tableau de bord de la Figure 1 montre une journée type : une ouverture à distance, une porte ouverte puis refermée, un bouton de sortie et un badge non enregistré.

Exploitation

8 · Moniteur

Le moniteur affiche passages et alarmes au moment où le contrôleur les envoie — l'équivalent du "Monitor" du logiciel d'origine, par exemple pour un accueil.

  • Dernier passage : photo (ou initiales), nom et badge de la personne, résultat (AUTORISÉ / REFUSÉ), motif, porte et sens (Entrée/Sortie), heure. Un badge non enregistré est indiqué comme tel.
  • Événements de la session : chaque événement reçu depuis l'ouverture de la page (jusqu'aux 300 plus récents), du plus récent au plus ancien.
  • Filtres en haut : un seul contrôleur, et Passages de badge uniquement pour masquer les événements de porte et les alarmes.
Remarque

Le moniteur n'affiche que ce qui arrive pendant qu'il est ouvert. Tout est enregistré de toute façon : les événements plus anciens sont dans l'Historique des événements. Si les passages n'apparaissent pas ici mais apparaissent plus tard dans l'historique, le serveur ne reçoit pas les événements en temps réel — voir Dépannage.

Exploitation

9 · Historique des événements

Tous les événements collectés auprès des contrôleurs, du plus récent au plus ancien. Utilisez les filtres pour trouver ce que vous cherchez :

  • Du / Au — période ;
  • Contrôleur et Porte ;
  • Personne ou Numéro de badge ;
  • Résultat — autorisés ou refusés uniquement.

Chaque ligne indique date et heure (heure du contrôleur), contrôleur, porte avec la flèche du sens (↘ entrée, ↗ sortie), type (Badge, Porte, Alarme), personne ou badge, résultat, motif et index de l'événement dans la mémoire du contrôleur. Exporter en CSV télécharge les événements filtrés dans la langue courante, prêts pour Excel.

D'où viennent les événements

Les événements arrivent en temps réel depuis les contrôleurs et sont aussi téléchargés automatiquement toutes les quelques minutes et chaque fois qu'un contrôleur redevient joignable : l'historique est complet même après des coupures du réseau ou du serveur. La mémoire du contrôleur est circulaire : si un contrôleur reste déconnecté si longtemps qu'elle se remplit, les événements les plus anciens sont écrasés.

Personnes présentes

La page Personnes présentes montre qui est à l'intérieur maintenant : pour chaque personne, le dernier passage de badge autorisé sur une porte qui compte pour la présence. Un passage sur une porte d'entrée met la personne à l'intérieur ; un passage sur une porte de sortie (ou sur le lecteur de sortie d'une porte à deux lecteurs) la met à l'extérieur. Le rôle de chaque porte se règle sur la page Portes : Entrée (par défaut), Sortie ou Non comptée.

Choisissez la période (aujourd'hui, 8 ou 24 dernières heures) : les personnes dont le dernier passage est plus ancien ne sont pas comptées. La page se rafraîchit seule toutes les 30 secondes ; Exporter en CSV télécharge la liste, par exemple pour l'appel lors d'une évacuation. Les personnes qui sortent avec le bouton de sortie (sans badge) ne sont pas visibles : pour un comptage exact, il faut un lecteur côté sortie.

Exploitation

10 · Présences

UHPPOTE Desk calcule le temps de travail à partir des passages sur les lecteurs marqués comme lecteurs de présence (sur la page Portes) — en général l'entrée principale. Seuls les passages autorisés comptent. La page a cinq onglets.

Rapport

Choisissez la période (du premier du mois en cours à aujourd'hui par défaut) et, si vous le souhaitez, un service ou une personne. La Synthèse de la période indique par personne : heures travaillées, heures prévues, heures supplémentaires, total des retards, jours d'absence et jours avec anomalies. Le Détail quotidien montre chaque jour avec son statut (Présent, Absent, Jour férié, Jour non travaillé, Congés, Permission, Maladie, Déplacement, Anomalie), première entrée, dernière sortie, heures travaillées, retard et tous les pointages ; ceux saisis à la main sont marqués d'un *. Exporter en CSV télécharge le détail.

Comment les heures sont calculées
  • Les pointages sont appariés dans l'ordre chronologique : entrée, sortie, entrée, sortie… Le sens du lecteur n'est pas nécessaire.
  • Avec une seule paire de pointages dans la journée, la pause de l'horaire est déduite automatiquement ; avec deux paires ou plus, la pause réelle est utilisée.
  • Un nombre impair de pointages (par exemple une sortie oubliée) est une anomalie : le dernier pointage est ignoré jusqu'à sa correction par un pointage manuel.
  • Retards et sorties anticipées tiennent compte de la tolérance de l'horaire. Le temps au-delà des heures prévues est en heures supplémentaires ; les jours non travaillés et fériés, tout le temps travaillé l'est.
  • Les horaires de nuit (finissant après minuit) sont attribués au jour où ils ont commencé.
  • Une personne sans horaire n'a pas d'heures prévues : seules les heures travaillées sont calculées.

Horaires

Un horaire définit heure de début et de fin, pause (minutes), tolérance (minutes) et jours travaillés. Un horaire qui se termine avant de commencer (par exemple 22:00–06:00) est un horaire de nuit. L'horaire s'attribue dans les détails de chaque personne (Personnes).

Jours fériés

Les jours où personne ne doit travailler. Ajoutez-les un par un (date et description) ou importez en un clic les jours fériés italiens d'une année, Pâques compris. Ajoutez au besoin les jours fériés locaux, fermetures et ponts.

Congés et absences

Enregistrez congés, permissions, maladies, déplacements et autres absences d'une personne pour une plage de dates. Ces jours ne comptent plus comme des absences dans le rapport.

Pointages manuels

Ajoutez un pointage que le lecteur n'a pas enregistré — par exemple une sortie oubliée — avec personne, date et heure, sens et motif. Les pointages manuels sont marqués d'un * dans le rapport et enregistrés dans le journal d'audit.

Exploitation

11 · Plaques

Une caméra avec reconnaissance de plaques (testée avec AgentDVR) envoie chaque plaque lue à UHPPOTE Desk, qui décide si le véhicule peut entrer, ouvre la porte, prend une photo depuis la caméra et enregistre la lecture. La page a trois onglets.

  • Lectures — chaque plaque lue, avec photo, heure, propriétaire, résultat (Autorisé, Plaque inconnue, Hors plage horaire…) et caméra. Filtrez par résultat ou cherchez par plaque ou nom. Les photos sont conservées 30 jours par défaut (PLATE_PHOTO_DAYS).
  • Plaques — les plaques connues du système. Une plaque appartient à une personne (ajoutée dans l'onglet Plaques de la personne : le véhicule passe là où la personne a une autorisation, dans sa plage horaire) ou à un lien invité (champ Plaques des véhicules : le véhicule passe tant que le lien est valable). Les plaques sont comparées en ignorant espaces, tirets et les caractères que les lecteurs confondent le plus (B/8, O/0, I/1, Z/2, S/5).
  • Caméras (administrateurs) — une ligne par caméra : la porte qu'elle ouvre, l'adresse de la photo, la pause après une ouverture (la voiture est encore devant la caméra) et Ouvrir la porte (désactivé = les lectures sont seulement enregistrées, pour tester une nouvelle caméra).

À la création d'une caméra, UHPPOTE Desk affiche deux adresses contenant la clé secrète de la caméra, à copier dans AgentDVR (liste des plaques connues et "Call URL") : la clé n'est affichée qu'une fois. Les lectures sont aussi publiées comme plate.granted / plate.denied pour les notifications, règles et webhooks ; les notifications Telegram et e-mail contiennent la photo. La configuration pas à pas est dans docs/PLATES.md.

Partie 3

Référentiel

Personnes, badges, invités et autorisations d'accès : qui peut aller où, et quand.

Référentiel

12 · Personnes

La liste montre matricule, nom, service, badges, validité et statut. Cherchez par nom, matricule ou numéro de badge. Cliquez sur une ligne pour ouvrir les détails ; Nouvelle personne en crée une.

Détails

  • Matricule (unique) et nom/prénom ; service, e-mail, téléphone, notes.
  • Accès valable du / au — en dehors de cette période, tous les badges de la personne sont refusés par les contrôleurs.
  • Code PIN clavier (jusqu'à 6 chiffres, 0 = aucun) — demandé par les lecteurs à clavier quand la porte fonctionne en mode "badge + PIN".
  • Horaire — pour les présences.
  • Photo — JPEG, PNG ou WebP ; elle est affichée dans le moniteur.
  • Active — désactivée, les badges de la personne sont retirés de tous les contrôleurs (l'historique est conservé). Pour les personnes qui partent, temporairement ou définitivement.

Badges d'une personne

Saisissez le numéro à 8 chiffres et Ajouter, ou utilisez Capturer depuis un lecteur : présentez le nouveau badge à un lecteur quelconque, il apparaît parmi les badges inconnus lus dans les 10 dernières minutes ; cliquez dessus pour l'attribuer. Une personne peut avoir plusieurs badges.

  • Perdu — remplace un badge perdu : l'ancien est marqué perdu et retiré des contrôleurs, le nouveau numéro reçoit aussitôt les mêmes autorisations.
  • Supprimer — retire le badge de la base et de tous les contrôleurs.

Autorisations d'une personne

Une ligne par porte de chaque contrôleur. Cochez les portes que la personne peut ouvrir et choisissez pour chacune Toujours ou une plage horaire. Premier badge permet à la personne d'"ouvrir" une porte qui utilise la fonction premier badge (voir Contrôleurs → Réglages avancés). Enregistrer les autorisations les envoie aussitôt aux contrôleurs.

Importer des personnes depuis un fichier CSV

Importer un CSV lit un fichier avec une ligne d'en-tête ; le séparateur (point-virgule, virgule ou tabulation) est détecté automatiquement. Colonnes reconnues :

ColonneNoms d'en-tête acceptésRemarques
Matriculecode, user no, consumer no, matricolaobligatoire ; un matricule existant met à jour cette personne
Nomlast name, lastname, name, cognomeobligatoire
Prénomfirst name, firstname, nome

Le résultat indique combien de personnes et de badges ont été créés ou mis à jour, et les lignes en erreur. Les personnes importées n'ont pas d'autorisations : attribuez-les ensuite, par exemple avec l'attribution groupée de la page Autorisations. Un export du logiciel Windows d'origine s'importe en général directement.

Référentiel

13 · Badges

Tous les badges connus de l'application, attribués ou libres, avec statut (Actif, Perdu, Désactivé) et date d'enregistrement. Le filtre Libres montre les badges pas encore attribués ; un badge libre peut être attribué depuis la liste.

  • Badges lus mais non enregistrés (dernière heure) — chaque badge inconnu présenté à un lecteur apparaît ici : cliquez pour l'enregistrer, libre ou directement attribué à une personne. Les numéros qui ne sont pas des badges Wiegand-26 valides sont grisés et ne peuvent pas être enregistrés.
  • Enregistrement par lot — enregistre toute une plage de numéros comme badges libres (jusqu'à 1000), par exemple une nouvelle boîte de badges aux numéros consécutifs.
Numéros de badge

Les contrôleurs n'acceptent que des numéros Wiegand-26 : code site 0–255 et code badge 0–65535, écrits site × 100000 + code. Le numéro imprimé sur beaucoup de badges (par exemple 100,58400 ou 0006612288) correspond à ce format ; en cas de doute, présentez le badge et lisez son numéro dans la liste des badges inconnus.

Référentiel

14 · Autorisations

L'équivalent de "Access Privilege" du logiciel d'origine : une matrice avec une ligne par personne et une colonne par porte. ✓ signifie toujours autorisé, un nombre signifie autorisé dans cette plage horaire. Filtrez les personnes pour trouver quelqu'un rapidement.

Avec l'attribution groupée, vous choisissez plusieurs personnes et plusieurs portes, éventuellement une plage horaire, et Accorder ou Révoquer applique toutes ces autorisations d'un coup — par exemple pour donner l'accès à l'entrée à tout un nouveau service.

Référentiel

15 · Services et zones

  • Les services organisent le personnel : ils servent à filtrer la liste des personnes et les rapports de présence. Un service peut appartenir à un autre (par exemple Production → Assemblage).
  • Les zones regroupent les contrôleurs, par exemple par bâtiment ou étage. Elles servent à limiter les opérateurs : un opérateur limité à une zone (et à ses sous-zones) ne peut ouvrir les portes et synchroniser que les contrôleurs de cette zone.

Utilisez Nouveau, modifier et supprimer ; supprimer un élément supprime aussi ses sous-éléments. Les personnes et contrôleurs d'un service ou d'une zone supprimés sont conservés, sans service ni zone.

Référentiel

16 · Invités

Un lien invité ouvre certaines portes pendant un temps donné, sans badge, application ni connexion : un livreur ou un technicien aujourd'hui, une entreprise de nettoyage chaque mardi soir, un ami pour le week-end. Les opérateurs ne créent des liens que pour les portes qu'ils peuvent eux-mêmes ouvrir ; les administrateurs les voient tous.

  • Portes et validité (du, au ; boutons Aujourd'hui, 7 jours…), éventuellement seulement certains jours et heures (par exemple lundi–vendredi 08:00–18:00) et un nombre maximal d'ouvertures.
  • Seulement sur le premier téléphone qui l'utilise (activé par défaut) : un lien transféré ne fonctionne pas sur un autre téléphone, et la tentative est enregistrée et notifiée.
  • PIN (4–8 chiffres), à donner séparément du lien ; après 5 PIN erronés, le lien est bloqué jusqu'à son déblocage.
  • Plaques des véhicules : les caméras de plaques ouvrent les portes du lien pour ces véhicules (voir Plaques).

Après l'enregistrement, le message à envoyer s'affiche avec les boutons Partager, WhatsApp et de copie. Le lien n'est affiché qu'à ce moment (seul son hachage est conservé) : s'il est perdu, Nouveau lien le remplace et l'ancien cesse de fonctionner. Depuis la liste, vous pouvez aussi révoquer un lien, le libérer du téléphone auquel il est lié et voir ses ouvertures.

La page de l'invité affiche le nom, la validité et un bouton Maintenez pour ouvrir par porte (un appui bref n'ouvre pas). Quand le lien n'est pas utilisable, elle explique pourquoi : pas encore valable, hors horaires, expiré, épuisé, révoqué ou bloqué. Ouvertures et refus apparaissent dans l'historique et sont publiés comme guest.opened / guest.refused. Détails : docs/GUESTS.md.

Partie 4

Configuration

Contrôleurs, portes et les règles qu'ils appliquent. La plupart de ces pages sont réservées aux administrateurs.

Configuration

17 · Contrôleurs

La liste des contrôleurs avec nom, numéro de série, adresse, firmware, état et dernier contact. Cliquez sur une ligne pour ouvrir sa page.

Trouver et ajouter un contrôleur

  1. Cliquez sur Rechercher sur le réseau, puis Lancer la recherche. Le serveur envoie un broadcast sur le réseau local et liste chaque contrôleur qui répond en quelques secondes, avec numéro de série, IP, MAC et firmware.
  2. Cliquez sur Ajouter à côté d'un contrôleur. Donnez-lui un nom, vérifiez adresse IP et port (60000), transport (UDP ; TCP seulement avec un firmware récent) et éventuellement une zone.
  3. Enregistrez : le contrôleur apparaît en ligne en quelques secondes. L'application le programme pour qu'il lui envoie ses événements, synchronise son horloge et télécharge ses événements stockés.

Un contrôleur peut aussi être ajouté manuellement avec son numéro de série. La recherche ne fonctionne que si le serveur est sur le même segment réseau que les contrôleurs ; avec Docker, le conteneur doit utiliser le réseau "host".

Contrôleur déjà utilisé ?

Si le contrôleur contient déjà des badges (par exemple du logiciel d'origine) et que la base de l'application n'en a pas, rien n'est supprimé à l'ajout. Importez d'abord les personnes, puis utilisez Synchronisation → Comparer pour voir les différences avant d'aligner.

Page du contrôleur — Diagnostic

Lus directement depuis le contrôleur : numéro de série, IP, passerelle, MAC, version et date du firmware, heure du contrôleur, nombre de badges stockés, dernier événement, signet de téléchargement, destination des événements (où le contrôleur envoie ses événements), anti-passback et erreur système. Le tableau Portes montre mode, délai d'ouverture, capteur et relais de chaque porte, tels qu'enregistrés dans le contrôleur.

  • Relire depuis le contrôleur rafraîchit les données.
  • Synchroniser l'heure règle l'horloge du contrôleur sur l'heure du serveur. Cela se fait aussi automatiquement quand l'écart dépasse 30 secondes.
  • Télécharger les événements télécharge tout de suite les événements pas encore collectés.

Réseau et configuration

  • Configuration dans l'application — comment l'application joint le contrôleur : numéro de série, nom, IP et port (IP vide = broadcast), transport, zone et Activé (un contrôleur désactivé n'est ni surveillé ni synchronisé). Retirer supprime le contrôleur et son historique de la base, sans modifier le contrôleur.
  • Adresse IP du contrôleur — modifie l'IP, le masque et la passerelle enregistrés dans le contrôleur. Elle sert à passer un nouveau contrôleur de son adresse d'usine à votre réseau. La commande est envoyée en broadcast, donc elle fonctionne même si l'adresse actuelle est injoignable ; ensuite l'application vérifie la nouvelle adresse.
  • Destination des événements (listener) — l'adresse à laquelle le contrôleur envoie chaque événement : le serveur. Elle est réglée automatiquement quand le serveur est configuré avec UHPPOTE_LISTENER_PUBLIC ; Configurer automatiquement l'applique tout de suite, Définir manuellement règle une autre adresse et l'intervalle d'envoi automatique de l'état.
Attention

Une adresse IP, un masque ou une passerelle erronés rendent le contrôleur injoignable. Il ne pourra alors être reconfiguré que depuis un ordinateur sur le même segment réseau, par une recherche sur le réseau.

Réglages avancés

Réglages valables pour tout le contrôleur. Ils sont enregistrés dans la base et envoyés au contrôleur avec Enregistrer et envoyer au contrôleur.

  • Interverrouillage — les portes d'un groupe ne peuvent pas être ouvertes en même temps (sas, par exemple portes 1 et 2) : une porte ne s'ouvre que lorsque les autres de son groupe sont fermées. Nécessite des capteurs de porte.
  • Anti-passback — empêche de repasser un badge à quelqu'un d'autre : après être entré par un lecteur d'un groupe, le badge doit sortir par un lecteur de l'autre groupe avant de pouvoir entrer à nouveau. Les groupements sont au chapitre 34.
  • Enregistrer les événements de porte et de bouton — enregistre aussi porte ouverte/fermée et bouton de sortie (recommandé).
  • Contrôle par PC — le contrôleur interroge le serveur avant d'accorder l'accès. Déconseillé : les portes ne fonctionnent plus quand le serveur est injoignable.
  • Envoi automatique de l'état — le contrôleur envoie son état au serveur toutes les N secondes en plus des événements (0 = événements seulement).
  • Claviers — cochez les lecteurs qui ont un clavier. Codes de porte : jusqu'à 4 codes par porte (jusqu'à 6 chiffres) qui ouvrent la porte saisis au clavier, sans badge.
  • Premier badge — aux heures et jours choisis, la porte reste fermée jusqu'à ce que la première personne autorisée avec l'autorisation "Premier badge" passe ; la porte passe alors au mode choisi (par exemple normalement ouverte) jusqu'à la fin de la période. Usage typique : l'entrée d'un magasin qui n'ouvre au public qu'après l'arrivée du responsable.
  • Options des lecteurs et des portes — les fonctions étendues correspondantes du logiciel du fabricant, écrites seulement quand Gérées par UHPPOTE Desk est activé et vérifiées par relecture : quatre passages = normalement ouverte (quatre passages d'affilée d'un badge valide maintiennent la porte ouverte, quatre autres la referment ; enregistré mais sans effet sur le firmware v9.f8 testé), lecteur silencieux sur les badges non valides (le contrôleur n'allume pas la LED du lecteur ; ces contrôleurs n'ont pas de sortie buzzer, donc le bip que le lecteur émet à chaque lecture reste), ne pas enregistrer les passages répétés du même badge (les passages suivants dans l'intervalle ouvrent la porte mais ne sont pas enregistrés à nouveau), porte en interrupteur (un passage bascule la serrure) et accès multi-badges (2–10 badges différents nécessaires pour ouvrir). Lire depuis le contrôleur affiche les valeurs que le contrôleur enregistre.

Carte d'extension

La carte d'extension d'alarme UHPPOTE UT0311-01A (vendue aussi sous le nom ACM-EC05) ajoute au contrôleur quatre relais d'alarme et une entrée incendie : on peut allumer une sirène, un voyant ou envoyer un signal à une centrale anti-intrusion ou incendie quand il se passe quelque chose aux portes. La configuration est dans l'onglet Carte d'extension ; Enregistrer et envoyer au contrôleur l'écrit puis la relit depuis le contrôleur pour la vérifier (le message indique vérifiée quand le contrôleur enregistre exactement ce qui a été envoyé) ; la synchronisation complète la réécrit.

  • Carte d'extension connectée — la configuration n'est écrite dans le contrôleur que si cette option est activée : les contrôleurs sans carte ne sont jamais touchés.
  • Porte ouverte trop longtemps après — secondes après lesquelles une porte laissée ouverte déclenche l'alarme Porte ouverte trop longtemps (25 s par défaut).
  • Code sous contrainte — un code saisi au clavier sous la menace : la porte s'ouvre normalement et l'alarme de contrainte se déclenche. Laissez vide pour garder le code enregistré dans le contrôleur.
  • Pour chaque sortie : la source (l'une des quatre portes, ou l'alarme anti-intrusion), le mode de sortie, les événements déclencheurs et la durée.
  • Options d'alarme — porte ouverte trop longtemps déclenche une alarme (sinon une porte laissée ouverte est seulement enregistrée ; nécessaire pour que les sorties réagissent), alarme badge non valide seulement après 3 tentatives et code sous contrainte seulement après un badge enregistré. Ce sont les options correspondantes des fonctions étendues du fabricant.
  • Lire depuis le contrôleur — affiche la configuration que le contrôleur enregistre réellement (lecture seule, rien n'est modifié), avec une indication si elle est identique à celle enregistrée. Copier dans le formulaire la prend comme point de départ, par exemple une configuration faite avec le logiciel du fabricant ; enregistrez pour l'appliquer.

État en direct. Pour un contrôleur avec Carte d'extension connectée, l'onglet Diagnostic affiche les quatre sorties (Allumée/Éteinte, sous le tableau des portes) et la tuile du tableau de bord indique celles qui sont allumées. Elles sont lues dans le même état que celui utilisé par la console du fabricant, à chaque vérification et, après un événement ou tant que quelque chose est allumé, toutes les 2 secondes jusqu'à ce que tout soit éteint. L'alarme incendie s'affiche aussitôt et disparaît quelques secondes après le relâchement de l'entrée.

Protocole reconstitué

Les commandes de la carte d'extension ne font pas partie du protocole public du contrôleur : elles ont été reconstituées à partir du logiciel du fabricant. Elles ont été vérifiées sur un UT0311-L04 (firmware v9.f8) avec une carte UT0311-01A connectée : ouverture forcée, porte ouverte trop longtemps, badge non valide, entrée incendie et sorties qui suivent un signal font commuter les relais, et l'état des sorties est lu correctement. Pas encore vérifiés : le code sous contrainte, la source alarme anti-intrusion et les entrées A1–A3. Une configuration faite avec le logiciel du fabricant est remplacée au prochain enregistrement : si vous voulez la garder, lisez-la d'abord et copiez-la dans le formulaire. Avant de retirer la carte, désactivez les sorties et enregistrez.

Maintenance

L'historique des synchronisations liste les synchronisations de ce contrôleur, avec opérateur, résultat et résumé. La réinitialisation d'usine efface les réglages réseau, la destination des événements, les badges et les événements du contrôleur. Les badges stockés sont d'abord enregistrés dans un fichier du dossier de sauvegarde du serveur ; pour confirmer, saisissez le numéro de série. Après une réinitialisation, le contrôleur doit être reconfiguré (IP, puis synchronisation).

Configuration

18 · Portes

Chaque porte de chaque contrôleur avec nom, mode, temps d'ouverture, état en direct et indication des présences. On peut l'ouvrir à distance d'ici. En modifiant une porte, vous changez :

  • Nom — utilisé partout dans l'application (tableau de bord, événements, autorisations).
  • Mode — Contrôlée (normal : s'ouvre avec un badge autorisé), Normalement ouverte (toujours déverrouillée) ou Normalement fermée (toujours verrouillée, même pour les badges valides).
  • Temps d'ouverture — secondes pendant lesquelles la serrure reste libérée après un passage autorisé, le bouton de sortie ou une ouverture à distance.
  • Active — les portes inactives (par exemple sorties non utilisées) sont masquées du tableau de bord et des autorisations.
  • Lecteur utilisé pour les présences — les passages sur ce lecteur deviennent des pointages.
  • Personnes présentes — Entrée, Sortie ou Non comptée : comment les passages sur cette porte comptent dans la page Personnes présentes.

Mode et temps d'ouverture sont envoyés aussitôt au contrôleur.

Configuration

19 · Plages horaires

Une plage horaire indique quand une autorisation est valable. Chaque plage a :

  • un ID de 2 à 254 (le numéro enregistré dans le contrôleur) et un nom ;
  • une période de validité (Valable du / au) ;
  • les jours de la semaine ;
  • jusqu'à trois intervalles horaires, par exemple 08:00–12:30 et 13:30–18:00 ;
  • éventuellement une plage liée : si un passage ne tombe pas dans cette plage, la plage liée est vérifiée aussi. La liaison permet de combiner des horaires différents selon les jours.

À l'enregistrement d'une plage, toutes les plages sont renvoyées à chaque contrôleur. Une plage utilisée par une autorisation ne peut pas être supprimée.

Exemple

"Heures de bureau" (2) = lun–ven 07:30–19:00 ; "Samedi matin" (4) = sam 08:00–12:30, liée à 2. Une autorisation avec la plage 4 permet l'accès les jours ouvrés aux heures de bureau et le samedi matin.

Configuration

21 · Synchronisation

Chaque modification est envoyée aux contrôleurs au moment où elle est faite. Si un contrôleur était injoignable à ce moment (éteint, panne réseau), on l'aligne ici. La page liste les contrôleurs avec leur état et ces commandes :

  • Comparer — lit tous les badges du contrôleur et montre les différences : badges à ajouter, à mettre à jour (autorisations, validité, PIN) et à retirer (présents dans le contrôleur mais pas dans la base). Rien n'est modifié.
  • Aligner les badges — applique ces différences aux badges.
  • Synchronisation complète (administrateurs) — renvoie configuration des portes, plages horaires, tâches, réglages avancés, carte d'extension et tous les badges. Avec beaucoup de badges cela peut prendre quelques minutes ; la progression est affichée en direct.
Récupération automatique

Quand un contrôleur redevient joignable sans aucun badge alors que la base en attend (réinitialisation d'usine, contrôleur remplacé), l'application lance d'elle-même une synchronisation complète. Toute autre différence est seulement signalée dans le journal du serveur, pour que des badges ne soient jamais supprimés sans la décision d'un opérateur.

Administration

Utilisateurs de l'application, traçabilité, maintenance du serveur et sécurité des comptes.

Administration

22 · Opérateurs

Les comptes qui peuvent se connecter à l'application. Pour chaque opérateur : nom d'utilisateur, nom affiché, rôle (voir chapitre 4), zones et dernière connexion.

  • Nouvel opérateur — choisissez nom d'utilisateur, nom, rôle et éventuellement les zones. Si vous laissez le mot de passe vide, un mot de passe temporaire est généré et affiché une fois : donnez-le à la personne, qui devra le changer à la première connexion.
  • Réinitialiser le mot de passe — génère un nouveau mot de passe temporaire.
  • Actif — un opérateur désactivé ne peut pas se connecter ; ses opérations restent dans le journal, comme lorsqu'un opérateur est supprimé.
  • Authentification à deux facteurs obligatoire pour — personne (facultative), administrateurs, opérateurs et administrateurs, ou tout le monde. Les personnes concernées doivent la configurer à leur prochaine connexion, avant d'utiliser l'application, et ne peuvent pas la désactiver. Le changement est enregistré dans le journal.
  • Colonne 2FA — qui a l'authentification à deux facteurs active. L'icône bouclier barré la réinitialise pour un autre opérateur qui a perdu son téléphone : il se connecte avec le seul mot de passe et peut la reconfigurer ; ses sessions et appareils mémorisés sont fermés.

Vous ne pouvez pas abaisser votre propre rôle, ni vous désactiver ou vous supprimer : il reste ainsi toujours au moins un administrateur.

Administration

23 · Journal d'audit

Le journal de chaque modification faite dans l'application et de chaque commande envoyée aux contrôleurs : date et heure, opérateur (ou system pour les opérations automatiques), action (par exemple open-door, put-card, sync-cards, login), cible, résultat et détails. Filtrez par action pour répondre à des questions comme "qui a ouvert hier la porte du bureau arrière ?".

Administration

24 · Système

  • Serveur — version, nom d'hôte, durée de fonctionnement, interfaces réseau et volume de données (contrôleurs, personnes, badges, événements).
  • Communication avec les contrôleurs — les réglages réseau du serveur : adresse locale, broadcast de recherche, port de réception des événements et destination programmée, c'est-à-dire l'adresse à laquelle les contrôleurs envoient leurs événements. Si elle n'est pas définie, un avertissement s'affiche : les événements n'arrivent alors qu'avec le téléchargement périodique, pas en temps réel.
  • Home Assistant (MQTT) — l'état de la connexion au broker, quand il est configuré (voir Home Assistant).
  • Sauvegarde de la base — une copie de la base est faite chaque nuit (à 02:00 par défaut, les 14 dernières sont conservées) dans le dossier backups des données du serveur. Créer une sauvegarde maintenant en fait une immédiatement, par exemple avant un gros import. Administrateurs uniquement.

25 · Changer le mot de passe

Depuis l'icône clé de l'en-tête. Saisissez le mot de passe actuel et deux fois le nouveau (au moins 8 caractères). Vos autres sessions ouvertes sont fermées. Si le mot de passe de admin est fixé par la variable ADMIN_PASSWORD du serveur, la page explique qu'il ne peut être changé que là.

Votre compte

26 · Authentification à deux facteurs

En plus du mot de passe, la connexion demande un code à 6 chiffres d'une application d'authentification sur votre téléphone (Google Authenticator, Microsoft Authenticator, Aegis, 2FAS, 1Password…). Chaque opérateur l'active depuis l'icône bouclier de l'en-tête (verte quand elle est active) :

  1. Activer et confirmez votre mot de passe.
  2. Scannez le QR code avec l'application, ou saisissez la clé affichée dessous, puis entrez le code affiché par l'application et Confirmer.
  3. Sauvegardez les 10 codes de récupération (copiez-les ou téléchargez-les) et gardez-les loin du téléphone : chacun remplace une fois le code de l'application, et ils ne sont plus affichés.

Dès lors, la connexion demande le code après le mot de passe ; les autres sessions ouvertes et appareils mémorisés (app mobile) sont déconnectés et se reconnectent avec le code. Un code n'est accepté qu'une fois, et les codes erronés comptent comme tentatives de connexion échouées. Sur la même page, vous pouvez générer de nouveaux codes de récupération ou la désactiver (mot de passe et code).

Téléphone perdu. Connectez-vous avec un code de récupération, ou un autre administrateur la réinitialise depuis la page Opérateurs.

Accès d'urgence pour les administrateurs

Si le seul administrateur a perdu à la fois le téléphone et les codes de récupération, définissez ADMIN_2FA_BYPASS=true sur le serveur (module complémentaire Home Assistant : option Emergency access without two-factor authentication) et redémarrez. Les administrateurs se connectent alors avec le seul mot de passe et peuvent désactiver leur authentification à deux facteurs sans code, même si elle est obligatoire (elle est alors reconfigurée avec le nouveau téléphone à la connexion suivante). Les opérateurs et les utilisateurs en lecture seule ne sont pas concernés : ils doivent toujours saisir leur code. Tant que la variable est définie, un bandeau rouge s'affiche sur chaque page et chaque connexion de ce type est marquée dans le journal. Retirez la variable et redémarrez dès que l'accès est rétabli.

Partie 6

Automatisation et intégrations

Règles, notifications, webhooks, jetons API, l'app mobile et Home Assistant. Administrateurs uniquement.

Administration

27 · Règles

Une règle dit quand il se passe quelque chose, seulement si certaines conditions sont réunies, alors faire quelque chose. Par exemple : un badge refusé à l'entrée principale après 20:00 → notification d'alarme ; la porte de l'entrepôt ouverte plus de 5 minutes → avertissement.

  • Quand — un événement quelconque (accès autorisé ou refusé, événement de porte, alarme, porte ouverte ou fermée, contrôleur hors ligne ou de nouveau en ligne, horaire inhabituel, refus répétés, lien invité, plaque) ou porte ouverte plus de un nombre de secondes (nécessite le capteur de porte).
  • Seulement si — portes, personnes ou badges, une plage d'heures (elle peut passer minuit) et des jours de la semaine.
  • Alors — envoyer une notification à certains canaux, appeler certains webhooks, ouvrir certaines portes. Chaque déclenchement s'affiche aussi dans l'application web : les alarmes restent à l'écran jusqu'à leur fermeture.
  • La gravité (information, avertissement, alarme) fixe l'emoji et la priorité des notifications ; le message peut utiliser {person}, {card}, {door}, {time}… ; la pause évite les déclenchements répétés.
Administration

28 · Notifications

Messages sur Telegram, par e-mail, ou vers ntfy et Gotify (serveurs push qui peuvent tourner sur votre propre NAS). Chaque canal a les événements qui envoient un message, un filtre de portes facultatif, la langue et le rapport quotidien facultatif (qui est entré, accès refusés, alarmes et anomalies des dernières 24 heures). Sur Telegram, les messages concernant une porte peuvent porter un bouton Ouvrir la porte, utilisable seulement par les utilisateurs Telegram indiqués dans le canal et pendant 15 minutes. Envoyer un test vérifie aussitôt le canal. Configuration de chaque type : docs/NOTIFICATIONS.md.

Administration

29 · Webhooks

Une requête HTTP POST vers d'autres systèmes (n8n, Node-RED, Make, un déclencheur webhook de Home Assistant, votre propre service) quand il se passe quelque chose : l'URL, les événements, un filtre de portes facultatif et des en-têtes supplémentaires. Chaque requête est signée avec le secret du webhook (X-UHPPOTE-Signature). Envoyer un test envoie une requête de test ; Envois liste les 100 dernières requêtes avec code de statut et contenu. Contenus et signature : docs/WEBHOOKS.md.

Administration

30 · Jetons API

Un jeton permet à un autre système d'utiliser l'API de UHPPOTE Desk sans connexion d'un opérateur : une domotique qui ouvre le portail, un script qui lit les événements, un logiciel RH qui crée des personnes. Niveaux d'accès : lecture seule, lecture + ouverture des portes, opérateur, administrateur ; éventuellement limité à certaines zones ou aux portes qu'il peut ouvrir, et avec une date d'expiration. Le jeton (uhd_…) n'est affiché qu'une fois ; désactivez-le ou supprimez-le pour le révoquer. Tout ce qui est fait avec un jeton est dans le journal comme token:<nom>. Points d'accès : docs/API-TOKENS.md.

Administration

31 · App mobile

La page /m est faite pour les téléphones et s'installe sur l'écran d'accueil comme une application. Elle montre les portes avec leur état en direct, les ouvre avec une confirmation, liste les derniers événements et reçoit des notifications push. L'icône téléphone de l'en-tête l'ouvre.

  • Mémoriser cet appareil à la connexion donne au téléphone sa propre connexion longue : sans expiration avec empreinte/Face ID enregistrés, sinon 30–180 jours.
  • L'ouverture d'une porte se confirme en maintenant le bouton ou, si l'administrateur le choisit, avec l'empreinte/Face ID du téléphone.
  • Installation, empreinte/Face ID et notifications push nécessitent HTTPS (PUBLIC_URL et un reverse proxy).

Dans Administration → App mobile, les administrateurs choisissent la confirmation d'ouverture et la durée de connexion, et voient chaque appareil mémorisé (opérateur, dernière utilisation, empreinte/Face ID, push) pour le révoquer. Détails : docs/MOBILE.md.

32 · Home Assistant

UHPPOTE Desk publie ses contrôleurs et ses portes sur un broker MQTT avec la découverte MQTT de Home Assistant : les appareils apparaissent tout seuls dans Home Assistant. Sous Home Assistant OS, le plus simple est le module complémentaire UHPPOTE Desk (dépôt https://github.com/alexbn71/UHPPOTE-Desk) : avec le module Mosquitto broker, la connexion se configure toute seule. Avec Docker, définissez MQTT_URL, MQTT_USERNAME et MQTT_PASSWORD ; l'état est sur la page Système.
