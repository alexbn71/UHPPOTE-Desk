# Outgoing webhooks

UHPPOTE Desk can send an HTTP `POST` request to other systems when something happens at the doors: n8n, Node-RED, Make/Zapier, Home Assistant webhook triggers, a chat bot, your own service.

Webhooks are managed by administrators in *Administration → Webhooks*. Each webhook has:

- a **URL** (`http://` or `https://`);
- the **events** it receives (see below);
- optionally a **door filter**: only events of the selected doors;
- optional **extra headers**, e.g. `Authorization: Bearer …` for receivers that require a token;
- a **signing secret**, generated by UHPPOTE Desk, used to sign every request.

The **Send test** button sends a `webhook.test` request right away (also to a disabled webhook) and shows the outcome. The **Deliveries** list shows the last 100 requests of each webhook, with status code, duration, attempts and the payload sent (click a row).

## Events

| Type | When |
|---|---|
| `access.granted` | Card swipe, access granted |
| `access.denied` | Card swipe, access denied (unknown card, no permission, outside the time profile…) |
| `door.event` | Door events recorded by the controller: remote opening, exit button, door opened/closed (the last two only when the controller records special events) |
| `alarm` | Alarms recorded by the controller: door open too long, forced open or closed, fire, theft prevention, 24×7 zone, emergency, exit button under threat. Controller power-on and reset are not sent |
| `door.opened` / `door.closed` | The door sensor changed, from the live controller status |
| `controller.online` / `controller.offline` | The controller became reachable / stopped answering |

Events from the controller older than 10 minutes (stored events downloaded when a controller comes back online) are saved in the history but are not sent.

With a door filter, door events are sent only for the selected doors, and `controller.*` events only for the controllers that have at least one of the selected doors.

## Request

```http
POST /your/path HTTP/1.1
Content-Type: application/json
User-Agent: UHPPOTE-Desk/0.1.0
X-UHPPOTE-Event: access.granted
X-UHPPOTE-Delivery: 5d0c1c55-3d0e-4d47-a6a8-3c7d9f1b2e10
X-UHPPOTE-Timestamp: 1791820800
X-UHPPOTE-Signature: sha256=8f2b…

{
  "id": "5d0c1c55-3d0e-4d47-a6a8-3c7d9f1b2e10",
  "type": "access.granted",
  "occurredAt": "2026-10-12T08:00:00.000Z",
  "controller": { "id": 1, "serial": 423187757, "name": "Entrance" },
  "door": { "id": 1, "number": 1, "name": "Entrance - Door 1" },
  "data": {
    "index": 1532,
    "eventType": 1,
    "card": 10058400,
    "personId": 12,
    "personName": "Rossi Mario",
    "granted": true,
    "direction": "in",
    "reasonCode": 1,
    "reason": "Card swipe",
    "timestamp": "2026-10-12 10:00:00"
  }
}
```

- `id` (also in `X-UHPPOTE-Delivery`) is the same at every retry of the same delivery: use it to ignore duplicates.
- `door` is `null` for `controller.*` events and for events without a door.
- `data` depends on the type: the fields above for `access.*`, `door.event` and `alarm`; `{ open, unlocked }` for `door.opened`/`door.closed`; `{ lastSeenAt, error }` for `controller.*`; `{ message }` for `webhook.test`.
- `data.timestamp` is the controller's local time; `occurredAt` is when UHPPOTE Desk sent the event (UTC).

## Responses and retries

- Any `2xx` reply is a success. Reply quickly (within 10 seconds) and do the work afterwards.
- Network errors, timeouts, `5xx` and `429` are retried after 2 s, 10 s and 60 s (4 attempts in all). Other replies (`3xx` redirects are not followed, `4xx`) are not retried.
- Each webhook has its own queue: requests arrive in order, and a slow receiver does not delay the other webhooks. If a receiver stays down, at most 500 requests wait in the queue; newer ones are dropped and logged.
- Pending retries are lost when UHPPOTE Desk restarts.

## Verifying the signature

`X-UHPPOTE-Signature` is `sha256=` followed by the hexadecimal HMAC-SHA256 of `<X-UHPPOTE-Timestamp>.<raw body>`, keyed with the webhook secret. Compute it on the **raw** body, before parsing the JSON, and reject requests whose timestamp is more than a few minutes old.

Node.js:

```js
import { createHmac, timingSafeEqual } from 'node:crypto'

function verify(secret, headers, rawBody) {
  const timestamp = headers['x-uhppote-timestamp']
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false
  const expected = 'sha256=' + createHmac('sha256', secret).update(`${timestamp}.${rawBody}`).digest('hex')
  const received = String(headers['x-uhppote-signature'] ?? '')
  return received.length === expected.length && timingSafeEqual(Buffer.from(received), Buffer.from(expected))
}
```

Python:

```python
import hashlib, hmac, time

def verify(secret: str, headers, raw_body: bytes) -> bool:
    timestamp = headers["X-UHPPOTE-Timestamp"]
    if abs(time.time() - int(timestamp)) > 300:
        return False
    digest = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(headers.get("X-UHPPOTE-Signature", ""), "sha256=" + digest)
```

n8n: in a *Webhook* node choose *Header Auth* and add the same header in UHPPOTE Desk (e.g. `X-Api-Key: …`), or verify the signature in a *Code* node with the Node.js function above (enable *Raw Body* in the Webhook node options).

## Security

- The secret and the extra headers are visible to administrators only. The audit log records the creation and changes of webhooks with the header **names** only, never their values.
- Use `https://` for receivers outside the local network.
- If a secret leaks, regenerate it (*Edit → Regenerate secret*) and update the receiver.
